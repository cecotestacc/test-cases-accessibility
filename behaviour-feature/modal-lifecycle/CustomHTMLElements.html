Case #12 modal-lifecycle
WCAG criteria
2.1.2 No Keyboard Trap — A  ·  2.4.3 Focus Order — A  ·  4.1.2 Name, Role, Value — A
Elements with errors
<modal-backdrop id="bad-modal"> and its inner <modal-panel>
Issues
  • ERROR 2.4.3 Focus is not moved into the dialog on open — keyboard users must Tab blindly to reach dialog content.
  • ERROR 2.1.2 Tab is not constrained — focus escapes into the page behind the open modal, which remains fully interactive.
  • ERROR 4.1.2 Background content is not marked inert or aria-hidden — screen readers can browse and interact with it while the modal is open.
  • ERROR 2.1.1 No Escape key handler — the dialog cannot be dismissed from the keyboard.
  • ERROR 2.4.3 Focus is not returned to #open-bad when the dialog closes.
  • PASS #good-modal: focus moves in on open, Tab is trapped, background is inert, Escape closes, focus returns to trigger.

Modal Lifecycle – Custom Elements

Violation: broken modal (focus not trapped, background not inert, Escape ignored)

Correct: full lifecycle (focus in → trapped → inert background → Escape → focus returns)

Broken Modal

Focus is not trapped here. Tab will leave this dialog. The page behind is not inert. Escape does nothing.

Accessible Modal

This dialog correctly:

  • Moves focus inside on open
  • Traps Tab and Shift+Tab within the panel
  • Marks the rest of the page inert
  • Closes on Escape
  • Returns focus to the trigger on close
